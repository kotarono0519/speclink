# speclink

要件・ユースケース・設計判断を溜め、**触っているコードから自動で引き当てる** Claude Code プラグイン。

過去に決めたことを毎回ゼロから考え直す、決定が覆ったのに文書が古いまま残る、
という 2 つの問題を、入口（差し込み）と出口（照合）の二段構えで防ぐ。

## 仕組みと中身は分ける

このリポジトリには**仕組みだけ**が入る。文書の実体は別リポジトリに置く。
プロジェクトごとに場所を指せるので、複数のプロジェクトで使い回せる。

```
speclink/            仕組み（このリポジトリ）
your-project-docs/   文書の実体（プロジェクトごとに用意する）
  requirements/      なぜこの機能が要るか
  usecases/          誰が何を達成するか（引き当ての鍵を持つ）
  decisions/         なぜその作りにしたか（却下案と理由）
  INDEX.md           自動生成。手で編集しない
  .speclink/index.json
```

## 導入

```shell
/plugin marketplace add kotarono0519/speclink
/plugin install speclink@speclink
```

有効にすると文書ディレクトリの場所を尋ねられる。後から変えるときは
プロジェクト直下に `.speclink.json` を置いてもよい。

```json
{ "docsDir": "../myapp-docs" }
```

どちらも無ければ speclink は何もしない（プロジェクトの邪魔をしない）。

## 何が起きるか

| いつ | 何が起きるか |
| --- | --- |
| 会話の開始時 | 文書の一覧（題名 + 1 行 + 対象範囲）が差し込まれる。本文は入らない |
| コードを編集する直前 | その場所に効く決定が差し込まれる。多いときは件数だけ |
| `/doc-new` | 決めたことを文書に残し、索引を更新する |
| `/doc-sync` | 変更と文書を突き合わせ、矛盾・更新漏れを一覧にする（書き換えはしない） |

## 設計の要点

- **引き当ては本文の検索ではなく、コードの場所と項目名で行う。**
  文書が増えても読む量が増えない（対象範囲に紐づく数件しか出ない）。
- **自動で書き換えない。** 提案までで止める。文書の価値は「人が確認した内容であること」だけ。
- **却下理由と業務の事情は生成しない。** 復元できない情報なので、聞くか空欄で残す。
- **範囲指定はフォルダ全体を指さない。** 発火しすぎは読み飛ばしを招き、仕組みごと死なせる。

詳しくは [`reference/format.md`](reference/format.md)。

## 索引の生成

```shell
node scripts/build-index.mjs [文書ディレクトリ]
```

範囲指定が粗い文書があると警告する。外部依存なし（Node のみ）。
