# speclink の働きを見る

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/stats.mjs" [日数] [--repo <リポジトリ名>]
```

既定は直近 30 日。記録はこのパソコンの中だけに残り、共有されない。

## 出力の読み方

| 見るところ | 判断 |
| --- | --- |
| コード編集の直前・差し込み率 | 5% 未満なら出なさすぎ（範囲指定が狭い） |
| 1 回あたりの件数 | 平均 3 件以上なら出しすぎ（範囲指定が粗い） |
| 関所の空振り率 | 80% 以上なら聞きすぎ（手がかりを絞る） |
| 一度も出ていない決定 | 触っているのに出ないなら範囲指定が狭い。触っていないだけなら問題ない |

## 数字を見た後にやること

**すぐ直さない。** どの文書の範囲指定を変えるか、ユーザーに示してから直す。
範囲指定は運用しながら調整するもので、機械的な最適化には向かない。

- 出しすぎ → よく出る文書の範囲指定を狭める（ファイル名まで、できれば項目名まで）
- 出なさすぎ → 触っているのに出なかった場面を聞き、その範囲を足す
- 空振りが多い → 関所の手がかりを絞る（speclink 側の作り直しになる）

## やらないこと

- 記録にコードの中身を書く（ファイル名・文書 ID・件数だけ）
- 数字だけを見て範囲指定を書き換える（触っていないから出ない、を見誤る）
