# 文書とコードの照合

**既に溜まっている文書と、今の変更が食い違っていないか**だけを見る。
「これから何を残すか」はコミット前の確認が担当なので、ここでは扱わない（同じことを二度出さない）。

**書き換えはしない。一覧を出して終わる。**
文書の価値は「人が確認した内容であること」だけで、自動更新するとその価値が消える。

呼ばれ方は 2 通り。どちらも同じ手順で動く。
- コミットしようとしたとき、**自動で起動する**（主）
- 人が `/doc-sync` と打ったとき（従）

書式の正典は `${CLAUDE_PLUGIN_ROOT}/reference/format.md`。

## 手順

1. **変更範囲を出す** — 引数で対象が指定されていればそれを使う。無ければ現在のブランチの差分
   （`git diff --name-only` と、ステージ済み・未コミットの分）を対象にする。
2. **文書を引き当てる** — 各ファイルについて、`active` な文書の `scope.paths` と `scope.fields` で照合する。
   本文の全文検索はしない。
3. **3 種類だけ報告する**（下記）。
4. **索引を更新する** — `node "${CLAUDE_PLUGIN_ROOT}/scripts/build-index.mjs"`

## 報告する 2 種類

| 種類 | 判定 |
| --- | --- |
| 矛盾の疑い | 変更後のコードが、その範囲の決定に反している |
| 文書が古い疑い | 決定が指す箇所が大きく変わり、決定の前提が成り立たなくなっている |

「紐づく文書が無い変更」は**ここでは扱わない**（コミット前の確認が同じものを見ている）。

各項目に、平易な 1 文で「何が・どこで・なぜ問題か」を書く。文書の id だけを並べない。

## 出しすぎない

- 判定に迷うものは出さない。誤検知が続くと読み飛ばされ、仕組みごと死ぬ。
- **該当が無ければ何も言わない**（自動で起動するので、毎回「ズレなし」と言うと邪魔になる）。

## 出力の最後に

矛盾や更新漏れが見つかったら、`/doc-new` で新しい決定を残すか、既存文書を直すかを尋ねる。
どちらにするかは人が決める。
