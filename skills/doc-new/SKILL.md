# 設計文書に残す

**これは Claude が従う手順で、人が打つコマンドではない。** speclink のフック（コミット前の確認・
決定が確定した瞬間）が反応したとき、Claude が自分でこの手順を実行する。
人が「決定を残して」と言ったときも同じ手順で動く。

人は「決めるたびにコマンドを打つ」ことをしない。それを前提に組む。
**人に何も聞かない。** 種類・置き場所・ファイル名は自分で決める。人しか知らないこと
（却下理由・業務の事情）が会話に出ていなければ、空欄のまま残す。

書式の正典は `${CLAUDE_PLUGIN_ROOT}/reference/format.md`。**最初に必ず読む。**
ひな形は `${CLAUDE_PLUGIN_ROOT}/templates/`。
文書の置き場所は `CLAUDE_PLUGIN_OPTION_DOCS_DIR`、無ければプロジェクト直下の
`.speclink.json` の `docsDir`。どちらも無ければ `/doc-init` がまだなので、それを案内して終わる。

## 手順

### 0. 書く前に取り込む（文書置き場が独立したリポジトリのとき）

複数のPCで同じ文書置き場を使うので、**読む・書く前に 1 回取り込む**（もう一方のPCの決定と番号が見えるように）。

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/sync-docs.mjs" pull "<文書の置き場所>"
```

対象外（コードのリポジトリの中・送り先なし）なら何もせずに終わる。失敗したら報告に一言添えて、手元のまま進める。

### 1. 何を残すかを自分で決める

会話とコードの変更から判断する。**聞かない。**

| 残すもの | 判定 |
| --- | --- |
| ユースケース | 担当者ができることが増えた／変わった |
| 決定 | 作り方に選択肢があり、何かを却下した |
| 何も残さない | 表示項目が増えただけ・体裁を直しただけ・内部の整理だけ |

**「何も残さない」が多数派になるのが正常。** 迷ったら残さない側に倒す。
コードを読めば分かることを書くと二重管理になり、仕組みごと信用を失う。

要件（業務の事情）はここでは作らない。コミットからは生まれない。

### 2. 既存の文書を探す

対象範囲（`scope.paths` / `scope.fields`）で照合し、該当する文書があるかを見る。

- **ある → 更新**（手順 3-A）
- **ない → 新規**（手順 3-B）

### 3-A. 更新する

**確認を取らずに書く。書いたら、変えた箇所を報告する。** 承認待ちにしない（記録が溜まらなくなる）。

```
UC-12 を更新しました

  ## 何を達成する
- 単価を直せる
+ 単価を、一覧を離れずに直せる

  ## 業務ルール
  （既存の行は触らない）
```

違っていれば人が 1 行で差し戻せる。書く前に止まるより安い。

- 直すのは**変更で実際に変わった箇所だけ**。ついでの整形をしない
- 業務ルール・想定外の流れなど、人が書いた行は勝手に消さない
- 決定文書も更新してよい（2026-08-09 決定）。ただし**却下した案とその理由は消さない**——
  この仕組みが防ごうとしているのは「同じ議論の繰り返し」なので、そこを消すと本末転倒になる

### 3-B. 新規に作る

1. 会話とコードから下書きを作る
2. **対象範囲を決める** — ファイル名まで、できれば項目名まで。フォルダ全体を指さない
3. 保存する — `<docs>/<種類>/<id>-<短い名前>.md`。id は既存の最大値 + 1

### 4. 人しか知らないことは空欄で残す

次のものは会話に出ていなければ**空欄で残す。聞かない。推測で埋めない。**

- **却下した案とその理由**（決定を残すとき。選択肢から選ばれたなら、選ばれなかった案がそのまま却下理由）
- 業務上の制約で、コードから読み取れないもの

空欄の印は `<!-- 未記入（コードから復元できない。分かったら書く） -->`。
後の会話でその情報が出たとき、この手順の 3-A（更新）で埋める。

### 5. 索引を更新する

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/build-index.mjs"
```

範囲指定が粗いと警告が出る。出たら直してから終わる。

### 6. コミットする（文書置き場が独立したリポジトリのとき）

文書置き場がコードと別の、文書だけのリポジトリなら、**確認を取らずにそのままコミットする**。
承認待ちは「あとで」を生み、書いた記録が未コミットのまま溜まる（記録に承認を挟まないのと同じ理由）。

- 登録するのは、今回書いた文書と自動生成の索引だけ（`git add` で個別に指定する。`-A` は使わない）
- 別の会話が書いてコミットせずに残した記録（会話の開始時に知らされる）も同じ扱いで入れる。中身を一読して壊れていなければ、聞かずにコミット・push する
- コミット前の確認（レビューの関所）は飛ばさない。止められたら手順どおりレビューしてから入れ直す
- コミットしたら**確認を取らずに push する**。断られたら取り込み直して 1 回だけやり直す（手で書かず次を使う）

  ```
  node "${CLAUDE_PLUGIN_ROOT}/scripts/sync-docs.mjs" push "<文書の置き場所>"
  ```

文書置き場がコードのリポジトリの中にあるときは、ここでコミットしない。コードの変更と一緒に、
そのリポジトリのいつもの手順（承認を取る）でコミットする。

### 7. 一言で報告する

何をどこに残したか、空欄のまま残した項目は何か、コミット・push したか。長く書かない。

## やらないこと

- コードを読めば分かることを書く（画面の項目一覧・処理の流れ・関数の説明）
- 操作手順を書く（画面を変えた瞬間に嘘になる）
- 却下理由・業務の事情の創作（空欄で残す）
- 人に何かを確認する（種類・置き場所・ファイル名は自分で決める。人しか知らないことは空欄で残す）
- 索引を手で書く（自動生成に任せる）
- 何も決まっていないのに文書を作る（多数派は「何も残さない」）
